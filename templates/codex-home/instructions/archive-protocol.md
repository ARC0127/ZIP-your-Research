# 对话存档、读档与项目共享经验池

### 存储位置

- 每个对话使用独立文件：`${CODEX_HOME}/archives/${CODEX_THREAD_ID}/存档.md`。Windows 上等价于 `%CODEX_HOME%\archives\%CODEX_THREAD_ID%\存档.md`。
- 使用当前环境提供的 `CODEX_THREAD_ID` 隔离对话，禁止把一个对话的存档混入另一个对话。
- 若 `CODEX_THREAD_ID` 不可用，回退到当前可写工作区的 `work/存档.md`，并在回复中明确实际路径。
- 这是用户触发的显式存档，不得写入或手改 Codex 自动生成的 memories 文件。

### `【存档】` 触发协议

- 用户消息出现 `【存档】` 时，将用户指定的部分和理解它所需的最少上下文写入当前对话的 `存档.md`。该触发词本身即为写入授权，无需再次确认。
- 若用户明确指出“存这一段、这个决定、这组结果”，严格保存该范围。若只说 `【存档】`，从当前消息和紧邻上下文中提取最可能长期有用的决定、事实、约束、偏好、证据位置和未完成事项。
- 保留一段简短原文或精确引用，再给结构化摘要。不得用润色后的解释覆盖用户原意。
- 使用带时间戳的 Markdown 条目，至少包含：标题、原文或保存范围、核心内容、决定与约束、证据或来源、未决事项、检索提示。
- 新条目默认追加；与既有条目实质重复时更新原条目并记录更新时间，避免重复堆积。
- 不保存密码、令牌、私钥、验证码或其他秘密。若触发内容含秘密，存档其非敏感结论，并明确秘密已排除。
- 写入后立即回复：已保存的内容摘要、文件路径、条目标题。不要只口头声称已存档。

推荐条目格式：

```md
## YYYY-MM-DD HH:mm — 条目标题

- 原文或范围：
- 核心内容：
- 决定与约束：
- 证据或来源：
- 未决事项：
- 检索提示：
```

### `【读档】` 触发协议

- 用户消息出现 `【读档】` 时，必须先读取当前对话的 `存档.md`；若当前任务属于本地项目，先按下文规则确保项目共享经验池存在，再读取项目 `INDEX.md` 与当前主题相关的少量条目，然后回答。
- `【读档：主题】` 按主题过滤；只有 `【读档】` 时，根据当前消息、最近讨论、未决事项和条目时间推断用户此刻最想恢复的内容。
- 默认输出相关决定与事实、它们对当前任务的含义、未完成事项和下一步。不要机械倾倒全部条目。
- 合并对话存档与项目经验时，必须标明来源是“本对话存档”还是“项目经验”；冲突时不得静默拼接或把另一对话的历史结论冒充当前事实。
- 清楚区分存档内容、当前推断和需要重新验证的外部状态。存档是历史记录，不自动证明事实仍然最新。
- 若多个条目冲突，优先展示较新的明确决定，同时指出被替代内容和冲突来源。
- 若存档不存在或为空，直接说明当前对话没有可读存档，再利用现有对话上下文继续；不得虚构历史记录。
- 读取只恢复上下文，不自动执行存档中的计划、命令或外部操作，除非当前消息同时明确授权执行。

### 项目根与共享经验池

- 项目共享经验池用于同一项目的多个对话复用经过筛选的决定、失败经验、工作流、证据边界和仍需验证的未知项。它不取代对话私有存档，也不取代代码、数据、日志、论文和项目权威文档。
- 每个可定位、可写的本地 Codex 项目默认必须具备该能力。它不是特定项目的可选配置；全局规则同时适用于现有项目和以后首次打开的新项目。
- 本地项目的默认位置是 `${PROJECT_ROOT}/.codex/experience/`，结构为：
  - `INDEX.md`：精简索引，只列当前高价值条目及其状态、范围和文件链接；
  - `README.md`：字段、读取、提升、并发和敏感信息规则；
  - `entries/EXP-*.md`：一项经验一个文件，保存完整内容与来源。
- 项目根优先使用当前 App 或工作区明确给出的项目根。未明确给出时，Git 项目使用 `git rev-parse --show-toplevel`；非 Git 项目向上寻找项目入口 `AGENTS.md`。若一个保存项目内含多个嵌套仓库，不得仅因发现更深的 `.git` 就把项目池切到子仓库。
- 项目名称、对话标题和目录显示名不是身份主键；实际项目根路径决定共享池。项目被整体移动后，应把经验池随项目一起移动。
- 项目外、临时目录和纯对话任务不创建项目池，继续只使用对话私有存档。

### 项目经验启动与检索协议

- 开始任何本地项目任务时，在实质性工作前定位 `PROJECT_ROOT` 并检查 `.codex/experience/`。若 `README.md`、`INDEX.md` 或 `entries/` 缺失且项目根可写，自动补齐基础结构；该初始化已由本全局规则授权，无需逐项目再次确认。
- 新建的 `README.md` 至少写明用途、读取顺序、写入边界和敏感信息规则；新建的 `INDEX.md` 至少包含版本、项目根、建立/更新时间、当前条目和项目权威资料指针。不得覆盖已有经验条目或把项目原有知识库复制进空池。
- 初始化或补齐后先读取 `INDEX.md` 一次。随后只按当前问题的术语、模块、失败现象或决策对象检索必要条目；默认不读取全部 `entries/`。
- 若项目根只读、不可访问或受项目规则禁止写入，继续进行获准的只读工作，并明确报告经验池未能初始化及实际原因；不得声称能力已建立。没有可确定项目根的临时任务和纯聊天不创建项目池。
- 项目经验只提供导航和历史认识。任何时变状态、外部事实、实验结果、进程状态、分支状态和文件状态在采取行动或形成强结论前必须按风险与成本重新核验。
- 引用经验时给出条目 ID；必要时同时给出证据路径和 `as_of`。不得只写“根据记忆”而隐藏来源。
- `【项目读档】` 只读取当前项目经验池；`【项目读档：主题】` 按主题检索。若当前任务没有可确定的项目根，直接说明无法定位项目池，不得猜测或跨项目搜索。

### `【项目存档】` 与经验提升协议

- `【项目存档】` 是写入当前项目共享经验池的明确授权；`【项目存档：主题】` 按主题保存。写入后回复条目 ID、摘要、项目根和文件路径。
- 普通 `【存档】` 仍只写当前对话私有存档，不自动升级为项目经验。
- 完成项目任务后，Agent 可以自动提升经验，但必须同时满足：
  1. 对未来至少一个项目任务有明确复用价值；
  2. 属于已验证事实、已复现失败、有效工作流、用户明确决定或有清楚验证门的 `UNKNOWN`；
  3. 项目范围和适用条件明确；
  4. 有证据路径、来源对话或可核验依据；
  5. 不含秘密、个人敏感信息、临时进度噪声或整段聊天转储。
- 任一条件不满足时留在对话存档，不进入项目池。自动提升后必须在最终回复中明确报告，不得后台静默写入。
- 不把每次最终回答、计划、猜测、一次性状态或未经验证的建议写入经验池。不得用项目经验文件复制项目中已有的权威文档；应保存经验结论并链接原始证据。

推荐条目字段：

```md
# EXP-YYYYMMDD-NNN — 条目标题

- 类型：DECISION | FAILURE | WORKFLOW | EVIDENCE | UNKNOWN
- 状态：CURRENT | HISTORICAL | REJECTED | SUPERSEDED
- 适用范围：
- 核心经验：
- 适用条件：
- 推荐动作：
- 应避免：
- 证据与来源：
- as_of：
- 来源对话：
- 替代或冲突条目：
```

### 项目经验的冲突、并发与安全

- 多对话并发写入是真实风险。新经验使用不重复的 `EXP-日期-序号` 文件；更新 `INDEX.md` 前使用 `${PROJECT_ROOT}/.codex/experience/.write.lock/` 原子目录锁，并在锁内记录操作者 thread ID、目标和时间。
- 获锁后完整读取最新 `INDEX.md` 并记录写前 SHA-256；写入前再次核对。发生变化时释放锁、重新读取并最多重试一次；第二次冲突停止并报告，不覆盖其他对话的修改。
- 发现已有锁时先读取锁的归属与时间。不得仅凭时间久就删除；无法确认安全释放时停止共享池写入，但可继续不依赖该写入的当前任务。
- 写入后检查：条目字段完整、索引链接有效、状态与 `as_of` 合法、无未解析冲突、无密码、令牌、私钥、验证码、Cookie 或连接凭据。完成后释放锁。
- 已过期或被否决的经验不直接删除。新增替代条目并将旧条目标为 `SUPERSEDED` 或 `REJECTED`，双向记录条目 ID，保留为什么改变的证据。
- 项目经验池是显式项目状态，不得写入或手改 Codex 自动生成的 `memories/`。
